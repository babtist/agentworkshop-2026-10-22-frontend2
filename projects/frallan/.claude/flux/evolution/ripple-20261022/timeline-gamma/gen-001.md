# Route/network propagation graph

Represent upcoming train events and shared route segments as a bounded graph,
then propagate advisory delays along verified dependencies.
Requires ordered routes, direction, trustworthy shared infrastructure mapping,
schedules, cancellations and a documented propagation/recovery model.

Advantage: can express downstream relationships beyond one station.
Limitation: the currently published API has none of the required topology.
Never infer shared physical tracks from station names or invent network data.
No extra Trafikverket polling or large timetable import without coordination.

Evaluation cases: branching routes, opposite directions, alternate tracks,
missing topology, cyclic dependencies and bounded memory/window expiry.
Next step: establish whether verified topology exists within workshop scope;
otherwise defer with a documented unmet prerequisite, not a fabricated score.
